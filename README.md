# ClimateCanary – GreenWings Team (G1T4)

ClimateCanary is a full-stack IoT system for monitoring and improving indoor room climate. Sensor stations collect environmental data such as temperature, humidity and CO2 pollution, which are processed and made available through a web application. Depending on their role, users can monitor their workplace, department, building, or the organization as a whole.

The system detects threshold violations and provides notifications and recommendations to help improve the room climate. The project combines a web application with Raspberry Pi and Arduino-based hardware components.

ClimateCanary was developed as a university project by the **GreenWings Team**. This repository is a public clone of the original university GitLab repository. All team members and university professors have approved the publication of the project.

### 🥈 Silver Award

The GreenWings Team received a **Silver Award** for ClimateCanary. The project was evaluated by a jury consisting of representatives from **five Austrian companies**.

## Available Users

The application comes with five users available for testing:

| Username   | Role                 | Purpose                                                                                       |
| ---------- | -------------------- | --------------------------------------------------------------------------------------------- |
| `employee` | `EMPLOYEE`           | Monitors the climate at their own workplace and in common areas of their department.          |
| `depthead` | `DEPARTMENT_MANAGER` | Monitors and manages climate information across their department.                             |
| `senior`   | `HIGHER_MANAGER`     | Views company-wide climate trends and aggregated information to support management decisions. |
| `building` | `BUILDING_MANAGER`   | Manages room climate data, thresholds, and climate-related recommendations across buildings.  |
| `sysadmin` | `SYSADMIN`           | Manages users, permissions, buildings, rooms, departments, and monitoring devices.            |

**Password for all users:** `passwrd`

These accounts can be used to test the different functionality and permissions available for each role.

The roles are separated by responsibility: **employees** monitor their own environment, **department managers** oversee their department, **higher management** receives aggregated company-wide information, **building managers** manage room climate and related settings, and **system administrators** handle the technical and organizational administration of the system.

## Usage & Configuration

### Webapp

#### Development

##### Frontend

First, generate the APIs required by the frontend from the OpenAPI specification in the `/webapp` folder:

```bash
mvn -q -B generate-sources -Dskip.frontend=true
```

The frontend is located in:

```text
/webapp/src/main/frontend
```

Install the dependencies and start the frontend in development mode:

```bash
npm i
npm run dev
```

The frontend will be available at:

```text
http://localhost:3000
```

##### Backend

For local backend development, comment out the `app` container in `/docker-compose.yml`:

```yaml
services:
#   app:
#     build:
#       context: ./webapp
#       args:
#         LOG_DIR: ${LOG_DIR:-/app/logs}
#     image: skel-app
#     container_name: "${TEAM_NAME:-local}-app"
#     ports:
#       - "${HOST_PORT:-8080}:8080"
#     environment:
#       SPRING_PROFILES_ACTIVE: prod
#       APP_JWT_SECRET: "${APP_JWT_SECRET}"
#       TEAM_NAME: "${TEAM_NAME:-local}"
redis:
    ...
postgres:
    ...
```

> **Optional:** The `postgres` container can also be commented out and replaced with an in-memory H2 database.

Start the required containers and the Spring Boot application:

```bash
docker compose up -d
mvn spring-boot:run
```

If you are using H2 instead of PostgreSQL, update `/webapp/src/main/resources/application.properties` before starting the application:

```properties
...
# database config
spring.datasource.driverClassName=org.h2.Driver
spring.datasource.url=jdbc:h2:mem:ClimateCanary;DB_CLOSE_DELAY=-1
spring.datasource.username=sa
spring.datasource.password=passwd
spring.jpa.properties.hibernate.dialect=org.hibernate.dialect.H2Dialect
spring.jpa.hibernate.ddl-auto=create
spring.h2.console.enabled=true
...
```

#### Production

To build and run the complete web application using Docker Compose, configure the required environment variables and start the containers:

```bash
export TEAM_NAME=<TEAM_NAME> # Optional, defaults to local
export APP_JWT_SECRET=<VALID_512_BITS_JWT_SECRET_KEY>
export LOG_DIR=<ABSOLUTE_DOCKER_PATH> # Optional, defaults to /app/logs

docker compose up --build -d
docker compose logs -f
```

To stop and remove the containers:

```bash
docker compose down
```

Example:

```bash
export TEAM_NAME=G1T4

docker compose up --build -d
docker compose logs -f
```

The web application will be available at:

```text
http://localhost:8080
```
